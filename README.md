# 自动重载

为 AI agent 设计的插件管理与自主热重载工具——并解决一个官方热重载不会告诉你的问题：

**「重载成功」不等于「真的生效」。**

## 它解决什么问题

AstrBot 自带的插件重载只做一件事：清模块缓存、重新 import。但有两类东西它管不到：

1. **平台适配器型插件**（QQ / Telegram 等常驻连接）重载后，跑着的旧实例仍持有旧模块代码——缓存清了，内存里跑的还是旧的
2. **插件自己 `create_task` 起的后台任务**（定时器 / 巡检 / 重试循环）没有登记表，重载后旧代码会继续跑

结果就是你可能遇到过的场景：回执说成功，行为却没变，只能靠发条消息试——还不一定试得出来。

本插件的做法：**每次重载返回自证回执**，逐层报告到底生效到哪一层；需要换血时，把旧实例、旧任务一并处理掉。

## 这个插件为谁而生：AI 的自主运维

传统的插件管理界面是为人类设计的：人改完代码，人点重载，人看控制台日志。但当维护插件的是 AI（LLM 驱动的 bot 主代理）时，这条链路断在两处：

1. **AI 看不到控制台**——重载成败、报错堆栈，它都拿不到，只能靠人类转述
2. **AI 无法确认生效**——回执说成功，行为没变，它没有手段自查，只能反复打扰人类

本插件的设计原点就是补上这条断链，让 AI 能自主完成「改代码 → 重载 → 验证生效」的闭环：

- **自证回执**：重载结果以结构化文本直接返回给 LLM——耗时、版本对比、模块缓存清理数、生效度结论全在返回值里，AI 读回执即知状态，无需人类翻日志
- **生效度四档 + 必须重启清单**：AI 能自主判断该「继续干活」还是该「报告人类重启」，而不是拿着一个模糊的"成功"猜
- **换手 / 回收开关**：AI 按任务需要按次传参（`handover_platforms=True` / `reclaim_tasks=True`），或由配置常开

### 怎么让你的 AI 用上它

1. **装上即用**：插件加载后，`hot_reload_plugin`、`plugin_list` 等 LLM 工具自动注册——只要你的 AstrBot agent 具备函数调用能力（默认具备），它就能在对话中自主重载插件、读取回执
2. **权限控制**：管理类 LLM 工具默认仅 ADMIN 可用；如需放行指定用户/agent 身份，配置 `owner_uids`
3. **子代理架构用户**：装上后 `update_subagent` / `subagent_health` / `subagent_snapshot` / `subagent_test` 一并注册，AI 可对子代理做四层体检、快照回滚、改人格后试音验证；不用子代理就关 `enable_subagent_tools`
4. **人类随时接管**：`/plugin` 系列指令与 LLM 工具并存，人类用聊天指令能做同样的事

这个插件的第一位用户，就是作者自己部署的 AI 主代理——它每天用这些工具自主重载插件、验证改动、体检子代理，本插件的每一项能力都经过它的真机日常使用验证。

## 核心能力

### 🧭 生效度评分

每次热重载的回执自带结论，四档：

```
✅ 热重载成功 · <插件名>
耗时 0.34s｜版本 2.10.0 → 2.10.0｜🟢 已加载｜模块缓存清理 15 个
🔗 绑定自检：全部指向当前在线模块，无孤儿
🧬 长活对象自检：无陈旧引用（后台任务/平台适配器均指向当前在线模块）
🧭 生效度：✓ 完全生效（模块/绑定/长活对象均指向当前代码）
```

`✓ 完全生效` / `◐ 部分生效`（注册表已换血、长活链路仍持旧代码）/ `⚠️ 底层改动没进内存` / `❌ 未生效`——不再需要"重载完发条消息试试"。

### 🚨 必须重启清单

自动检测 `astrbot/core` 下"源文件比 `.pyc` 新"的模块——改动在进程导入之后才落盘，内存里没有它，任何插件重载都救不了。回执会直接点名让你重启，而不是让你白忙一场。判据不依赖系统时钟（实测部分环境 `/proc/uptime` 不可信，误报比不报更坏）。

### 🔄 平台实例换手（默认关）

针对上面第 1 类问题。开启后：重载完成 → 停旧实例（连同它的任务一起收走）→ 按新代码重挂 → 自检确认。实测真机断线重连约 **1 秒**（0.99s）。

三道安全闸：拿不到配置跳过、`enable=false` 跳过、别家实例零动作。

### 🧹 陈旧任务回收（默认关）

针对上面第 2 类问题。只取消"归属本插件 **且** 仍持旧模块代码"的任务——新任务、别家插件、当前调用者自身一律不碰（零误杀验证过）；吞掉 `CancelledError` 的顽固任务只记录不强杀。

### 子代理三件套（v1.0.1）

如果你在用 AstrBot 的子代理编排，这三个工具把"改完人格不知道改没改上"变成可验证的事：

- **🩺 `subagent_health` 运行时体检**——对照四层抓异常：编制表（config）↔ 运行时实例（handoffs）↔ 人格源（persona DB）↔ provider 可用性。专治：在编但未挂载、人格缺失导致的串台回落、改人格后没重载（运行时还跑旧 instructions）、provider 失效。单次体检输出逐项核对结果（实测 11 项全绿示例见下）
- **📸 `subagent_snapshot` 编制快照**——`save` 一次性备份 orchestrator 配置段 + 全部相关人格（prompt / begin_dialogs / tools）；`list` 列历史；`rollback` 一键恢复（人格存在才恢复，不存在跳过并明示，不做半恢复）。存于 `data/plugin_data/astrbot_plugin_manager/subagent_snapshots/`，纯本地
- **🎤 `subagent_test` 试音台**——用子代理的人格与 provider 直接发一条测试消息，拿回原始回复（不转发给用户）。调人格时改一段试一段，session 隔离不留上下文，60s 超时

不用子代理功能？配置里把 `enable_subagent_tools` 关掉，这四个工具（含 `update_subagent`）整体消失，不占工具列表。

## 聊天指令

| 指令 | 说明 |
|------|------|
| `/plugin help` | 查看帮助 |
| `/plugin list` | 查看所有插件（按启用/禁用/保留分组） |
| `/plugin info <名称>` | 查看插件详情 |
| `/plugin enable <名称>` | 启用插件 |
| `/plugin disable <名称>` | 禁用插件 |
| `/plugin reload <名称>` | 重载插件 |
| `/plugin install <GitHub URL>` | 从仓库安装插件（需开启配置） |
| `/plugin uninstall <名称>` | 卸载插件（需开启配置） |
| `/plugin update <名称>` | 从仓库更新插件 |

另有 LLM 工具：`hot_reload_plugin`、`plugin_list`，以及上节的子代理四工具。

## 配置说明

在 AstrBot 插件配置页面找到「自动重载」：

| 配置项 | 默认 | 说明 |
|--------|------|------|
| allow_install | 关 | 允许聊天指令安装插件 |
| allow_uninstall | 关 | 允许聊天指令卸载插件 |
| hot_reload_handover_default | 关 | 每次热重载自动执行平台实例换手（工具传参可按次覆盖） |
| hot_reload_reclaim_default | 关 | 每次热重载自动回收陈旧后台任务（工具传参可按次覆盖） |
| enable_subagent_tools | 开 | 启用 update_subagent / subagent_health / subagent_snapshot / subagent_test 四个子代理 LLM 工具 |
| owner_uids | 空 | 免 ADMIN 放行的用户 ID 列表（管理类 LLM 工具的调用白名单） |

> 设计原则：换手与回收默认关闭。先看回执 🧬 行报不报陈旧，确认需要换血再开——日常重载零代价。

## 安装

下载本插件文件夹，放入 AstrBot 的 `data/plugins/` 目录，重启 AstrBot。

或从 AstrBot 插件市场搜索「自动重载」一键安装。

## 兼容性声明

本插件适配 AstrBot **4.16+**。指令类功能（`/plugin list` 等）仅依赖公开接口，兼容性最好。

深度热重载与子代理三件套依赖 AstrBot 内部模块（`astrbot.core.star.updater`、`astrbot.core.persona_mgr`、`astrbot.core.subagent_orchestrator` 等）——这些内部 API **未承诺稳定**，官方版本升级可能导致相应功能失效。遇到问题时请先核对你的 AstrBot 版本，并在 issue 中附上回执与日志。

## 必须重启的场景（边界声明）

热重载不是银弹，以下场景请老实重启：

- 改动 `astrbot/core/**`（回执会主动报 🚨）
- 平台端口绑定 / webhook 路径变更
- 全局 `config.yaml` 结构变更、数据库 schema 迁移

## 注意事项

- 卸载插件会删除插件目录，请谨慎操作
- `install` 会执行 `pip install`，请确认仓库来源可信后再开启
- 本插件无法卸载自身（防止把自己搞没）
