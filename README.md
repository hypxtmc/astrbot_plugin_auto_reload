# 自动重载

AstrBot 自带的插件重载只做一件事：清模块缓存，重新 import。剩下的事它不管。

有两类东西重载完照旧跑旧代码：

1. 平台适配器型插件（QQ / Telegram 这类常驻连接）——旧实例还活着，缓存清了也没用
2. 插件自己 `create_task` 起的后台任务（定时器、巡检、重试循环）——没有登记表，谁也不知道它们还在跑

于是就有那个熟悉的场景：回执说成功，行为没变。发条消息试试？还不一定试得出来。

这插件干的事，是每次重载给你一份自证回执，逐层说清到底生效到哪一层。该换血的地方，把旧实例和旧任务一并处理掉。

## 它是给谁用的

传统插件管理界面是给人类设计的：人改代码，人点重载，人看控制台。但维护插件的如果是 AI，这条链断在两处：

1. AI 看不到控制台。重载成败、报错堆栈，它都拿不到，只能等人转述
2. AI 没法确认生效。回执说成功、行为没变，它没有手段自查，只能反复来问

所以这插件把重载结果做成结构化文本，直接返回给 LLM：耗时、版本对比、模块缓存清理数、生效度结论，全在返回值里。AI 读回执就知道状态，不用人去翻日志。

它还给出「必须重启」的明确结论。AI 能自己判断该接着干活，还是该报告人类重启，而不是拿着一个模糊的「成功」猜。

### 两个场景

**一、人不用碰控制台**

装上之后对 bot 说人话就行：

> 「重载一下 memobird 插件」
> 「把图床插件重载一遍，刚才改了配置」

AI 收到就自己调 `hot_reload_plugin`，把回执直接答给你。不用记命令格式，不用开 WebUI。

**二、AI 修完自己重载**

传统流程里 AI 帮你改完代码，事情会断在这儿——还得有人去控制台手动重载一遍。装上这插件，AI 改完代码自己重载、自己读回执、自己判断：

> `✓ 完全生效` → 接着干活
> `⚠️` → 报告需要重启

### 怎么让 AI 用上

1. **装上即用**：插件加载后 `hot_reload_plugin`、`plugin_list` 等 LLM 工具自动注册。只要你的 agent 有函数调用能力（默认有），一句自然语言就能让它自主重载
2. **权限**：管理类 LLM 工具默认仅 ADMIN 可用。要放行指定用户，配 `owner_uids`
3. **用子代理的话**：`update_subagent` / `subagent_health` / `subagent_snapshot` / `subagent_test` 一并注册。不用就关 `enable_subagent_tools`
4. **人类随时接管**：`/plugin` 系列指令和 LLM 工具并存，聊天里能做同样的事

这插件的第一位用户是作者自己部署的 AI 主代理，每天都在用。真机上撞出来的问题，比设计时想出来的多。

## 核心能力

### 生效度评分

每次重载的回执自带结论，四档：

```
✅ 热重载成功 · <插件名>
耗时 0.34s｜版本 2.10.0 → 2.10.0｜🟢 已加载｜模块缓存清理 15 个
🔗 绑定自检：全部指向当前在线模块，无孤儿
🧬 长活对象自检：无陈旧引用（后台任务/平台适配器均指向当前在线模块）
🧭 生效度：✓ 完全生效（模块/绑定/长活对象均指向当前代码）
```

`✓ 完全生效` / `◐ 部分生效`（注册表换了血、长活链路还持旧代码）/ `⚠️ 底层改动没进内存` / `❌ 未生效`。

不用再「重载完发条消息试试」。

### MRO 旧血自检

多模块插件有个藏得深的坑：`@llm_tool` 的壳函数在 `main.py`，方法体却在 `dispatch.py` 这类子模块里。壳函数的 `__globals__` 永远是新鲜的 `main.py` 字典，绑定自检看过去一片绿——可类上挂的基类要是旧对象，壳里那句 `super().xxx()` 就顺着旧 MRO 走到旧方法体去了。

1.1.0 加了独立一道：扫 MRO 上属于本插件的基类，逐个比对 `sys.modules` 里的同名类对象。对不上就明说「⚠️ 假绿，必须重启」，并点名是哪个 Mixin。

在这之前，这种情况会安静地报「完全生效」。

### 必须重启清单

自动检测 `astrbot/core` 下「源文件比 `.pyc` 新」的模块——改动在进程导入之后才落盘，内存里没有，任何插件重载都救不了。回执直接点名让你重启，不让你白忙。

判据不依赖系统时钟。有些环境 `/proc/uptime` 不可信，误报比不报更坏。

### 平台实例换手（默认关）

针对第一类问题。开启后：重载完成 → 停旧实例（连它的任务一起收走）→ 按新代码重挂 → 自检确认。真机实测断线重连约 1 秒（0.99s）。

三道安全闸：拿不到配置跳过、`enable=false` 跳过、别家实例零动作。

### 陈旧任务回收（默认关）

针对第二类。只取消「归属本插件**且**仍持旧模块代码」的任务——新任务、别家插件、当前调用者自身一律不碰（零误杀验证过）。吞掉 `CancelledError` 的顽固任务只记录，不强杀。

### 子代理三件套

在 AstrBot 子代理编排里，这三个工具把「改完人格不知道改没改上」变成能验证的事：

- **`subagent_health`** 四层体检：编制表（config）↔ 运行时实例（handoffs）↔ 人格源（persona DB）↔ provider 可用性。专治在编未挂载、人格缺失导致的串台回落、改完人格没重载、provider 失效
- **`subagent_snapshot`** 编制快照：`save` 备份 orchestrator 配置段和全部相关人格；`list` 列历史；`rollback` 一键恢复（人格不存在就跳过并说明，不做半恢复）。存在 `data/plugin_data/astrbot_plugin_auto_reload/subagent_snapshots/`，纯本地
- **`subagent_test`** 试音台：用子代理的人格和 provider 直接发一条测试消息，拿回原始回复，不转发给用户。调人格时改一段试一段，session 隔离，60s 超时

不用子代理？把 `enable_subagent_tools` 关掉，四个工具（含 `update_subagent`）整体消失，不占工具列表。

## 聊天指令

| 指令 | 说明 |
|------|------|
| `/plugin help` | 查看帮助 |
| `/plugin list` | 查看所有插件（按启用/禁用/保留分组） |
| `/plugin info <名称>` | 查看插件详情 |
| `/plugin enable <名称>` | 启用插件 |
| `/plugin disable <名称>` | 禁用插件 |
| `/plugin reload <名称>` | 重载插件 |
| `/plugin install <GitHub URL>` | 从仓库安装（需开启配置） |
| `/plugin uninstall <名称>` | 卸载（需开启配置） |
| `/plugin update <名称>` | 从仓库更新 |

另有 LLM 工具 `hot_reload_plugin`、`plugin_list`，以及上面的子代理四工具。

## 配置

在插件配置页找到「自动重载」：

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `allow_install` | 关 | 允许聊天指令安装插件 |
| `allow_uninstall` | 关 | 允许聊天指令卸载插件 |
| `hot_reload_quick_default` | 开 | 默认走定向快路径（只重导目标插件，1-3 秒）。关掉则每次都全量 |
| `hot_reload_handover_default` | 关 | 每次重载自动做平台实例换手（工具传参可按次覆盖） |
| `hot_reload_reclaim_default` | 关 | 每次重载自动回收陈旧后台任务（工具传参可按次覆盖） |
| `enable_subagent_tools` | 开 | 启用子代理四个 LLM 工具 |
| `owner_uids` | 空 | 免 ADMIN 放行的用户 ID 列表 |

换手和回收默认都关着。先看回执 🧬 行报不报陈旧，确认需要换血再开——日常重载零代价。

## 安装

下载本插件文件夹放进 AstrBot 的 `data/plugins/`，重启。

或从 AstrBot 插件市场搜「自动重载」一键装。

## 兼容性

适配 AstrBot **4.16+**。

指令类功能（`/plugin list` 等）只依赖公开接口，兼容性最好。

深度热重载和子代理工具依赖 AstrBot 内部模块（`astrbot.core.star.updater`、`astrbot.core.persona_mgr`、`astrbot.core.subagent_orchestrator` 等）。这些内部 API 官方没承诺稳定，版本升级可能让相应功能失效。遇到问题先核对版本，附上回执和日志开 issue。

## 该重启就重启

热重载不是银弹。以下场景老实重启：

- 改了 `astrbot/core/**`（回执会主动报 🚨）
- 平台端口绑定 / webhook 路径变更
- 全局 `config.yaml` 结构变更、数据库 schema 迁移

## 注意

- 卸载插件会删掉插件目录，手别抖
- `install` 会执行 `pip install`，确认仓库来源可信再开
- 本插件无法卸载自身（防止把自己搞没）
